# Detectors

Each detector is a pure function in `src/detectors/` that reads one of the player's moves and answers yes or no. Only moves that the analysis classed as an inaccuracy, mistake or blunder get tags. A move can have several tags.

Detectors use the rules of chess through chessops and the engine lines saved by the deep pass. They were written for this project. None of the code comes from the Lichess puzzle tagger.

Tests live in `tests/unit/detectors.node.test.ts`. Fixtures are in `tests/fixtures/detector-positions.ts`, with at least three positions where each tag must fire and three where it must not. Engine lines for the fixtures are saved in `tests/fixtures/detector-lines.json` (Stockfish 19 lite, depth 16, MultiPV 3). To rebuild them after changing fixtures, run `UPDATE_FIXTURES=1 npx vitest run tests/unit/detectors.node.test.ts` and read `test-results/detector-report.txt`.

Bump `DETECTOR_VERSION` in `src/detectors/index.ts` when a definition changes. The app then retags stored games without analyzing them again.

## Shared definitions

- **Values.** Pawn 1, knight 3, bishop 3, rook 5, queen 9.
- **Static exchange (SEE).** The material one side wins by capturing on a square, recapturing with the least valuable piece each time. Pins are ignored.
- **Best line.** The deep pass's first line from the position before the move.
- **Reply.** The opponent's best answer to the played move, from the engine line saved with it.

## Known limits

- SEE ignores pins, so a pinned defender still counts as a defender.
- `kingSafety`, `pawnStructure` and `pieceActivity` describe measured changes, not causes. A move can change these features and lose for another reason.
- The fork rule counts any undefended piece as a target, so a single attack on two loose pieces counts as a fork even when one of them is a minor piece and the attacker is a queen.
